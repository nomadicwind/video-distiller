# M15 最清晰拉取（B 站 cookie + 码率优先排序）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** B 站拉取默认取最清晰版本。实测证据（2026-10-06，BV11L8z68Eso）：无 cookie 时 B 站封锁大会员档（1080P60 missing 提示），且 yt-dlp 默认编码偏好选中 AV1 2.9Mbps 而非 AVC 4.4Mbps；带用户 Chrome cookie 后解锁 1080p50 @ 10Mbps。用户已授权使用其身份（cookie 本地读取，仅发往 B 站）。

**Architecture:** 纯后端 ingest 小改：①环境变量驱动的 cookie 注入（`VD_YTDLP_COOKIES_BROWSER` → `--cookies-from-browser`；`VD_YTDLP_COOKIES` → `--cookies <file>`，前者优先）；②格式排序 `-S res,fps,tbr`（分辨率→帧率→总码率，压过默认编码偏好）。冻结（YoutubeDL API）与子进程两路参数**同步**（M13 既有双路约定）。

**Spec:** 本计划 Global Constraints 即契约。

## Global Constraints

- **cookie 红线**：cookie 值不得出现在日志/报错/API 响应/前端任何位置；代码只传递 env 的浏览器名或文件路径给 yt-dlp；两个 env 都未设时行为与现状完全一致（零 cookie 参数）
- **双路同步**：子进程路径（argv：`--cookies-from-browser <v>` / `--cookies <path>`、`-S res,fps,tbr`）与冻结路径（opts：`cookiesfrombrowser: (browser,)`、`cookiefile`、`format_sort: ['res','fps','tbr']`）参数语义一一对应；两路都测
- `VD_YTDLP_COOKIES_BROWSER` 允许 yt-dlp 的 `浏览器[:profile]` 语法原样透传（如 `chrome`、`edge`）；两 env 同设时 BROWSER 优先并忽略文件（报告注明）
- 后端测试基线 199 只增不减；前端零改动（189 终验一跑）
- 文档如实：README「M15」段 + packaging/使用说明.txt（Windows 注意：Chrome 127+ 的 App-Bound Encryption 使 `--cookies-from-browser chrome` 在 Windows 上常不可用——推荐 Firefox/Edge 或浏览器扩展导出 cookies.txt 配 `VD_YTDLP_COOKIES`；macOS Chrome 可用，首次可能弹钥匙串授权）；已下载的旧视频不会自动变清晰，需重新拉取为新视频（标注不迁移）
- conventional commit + 尾注 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
